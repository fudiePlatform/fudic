Dónde TextMate acierta y dónde falla

Acierta en casi todo porque la inyección delega el interior de cada región al grammar nativo: Variant se colorea como alias de tipo TS de verdad, signal( como llamada a función, :host y .body anidado como CSS real, viewport con tu scope propio de hidratación.

Falla en los bordes, que es justo lo que anticipábamos y lo que el LSP semántico arregla:

  • @(variant === 'highlight') dentro de un atributo: TextMate abre source.ts pero al ser regex sin estado, expresiones con paréntesis anidados o template literals con ${} rompen el cierre en casos profundos.
  • @if (expanded.value) { Cerrar } else { Abrir }: el texto suelto Cerrar/Abrir no se distingue de markup; no hay forma sin estado de saber que es contenido y no un identificador.
  • @press se colorea como evento por posición, pero TextMate no puede validar que sea un custom event declarado — eso es semántico.
  • El anidamiento CSS nativo (.body dentro de .card) depende de que el grammar de CSS lo soporte; en bordes con Razor mezclado, el conteo de llaves se le escapa.

Por eso la estrategia es TextMate para el arranque instantáneo y semantic tokens desde tu parser para la verdad. Aquí ves exactamente el suelo del que parte.
