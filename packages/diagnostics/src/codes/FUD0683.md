# FUD0683 — `inject()` in a route's `@server`
**retired** · SDD-38

It reported `inject(…)` written in a route's `@server`, when a route had no ambient container and resolved through `ctx.inject(…)`.
SDD-56 made the request's container ambient, kept per request in an `AsyncLocalStorage`, so `inject(…)` and `publish(…)` work there as written. The number is not reused.
**Replaced by:** nothing: `inject(…)` in a route's `@server` is no longer an error.
